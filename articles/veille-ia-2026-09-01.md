# WebGPU kernels (Hugging Face) : package npm, 207 kernels, et suite Fleet

## Points clés
- Hugging Face publie @huggingface/kernels (npm) et une collection initiale de 207 kernels WebGPU sur le Hub (repo webgpu-kernels). Chaque kernel est versionné et documenté (manifest, cartes, cas de correction et de benchmark, exemples d’usage).
- Fleet est une application web (in-browser) pour exécuter des tests de correction et de performance sur votre GPU ; avec consentement, chaque exécution ajoute des preuves privées pour améliorer variantes et règles de sélection.
- L’accès et l’exécution exigent un navigateur/GPU/drivers compatibles WebGPU ; disponibilité vérifiable en JavaScript par "gpu" in navigator.
- Exemple de comparaison mesurée (Apple M4, ONNX Runtime Web vs ces kernels) : gain géométrique moyen 2,57x, médiane 1,90x sur 809 cas comparables ; certains cas particuliers montrent des accélérations extrêmes (ex. 10 000x) — mesures limitées au temps de calcul GPU, hors overheads de setup/IO.
- Les kernels supportent variantes (par forme d’entrée, type de données, stratégies d’indexation) et des contrats de version distincts des opsets ONNX, facilitant l’évolution sans casser l’API JS.

## Points clés
- Deux jeux de test ajoutés au Open ASR Leaderboard : Monsoon en‑IN (Indian English) et Monsoon hi‑IN (Hindi), chacun en split public et split privé.
- 4 888 locuteurs au total, jeux speaker‑disjoint, chaque segment contient 18 colonnes dont 12 métadonnées démographiques (district, âge, genre, appareil, etc.).
- Conception axée sur variance plutôt que volume : plus de la moitié des locuteurs n’apparaissent qu’une seule fois ; aucun locuteur, région ou modèle d’appareil ne domine (>2,1% par modèle d’appareil).
- Hindi : références multi‑variantes (lattices) et mesure OIWER (Orthographically‑Informed WER) ; implémentation ouverte : package voi‑oiwer sur PyPI.
- Collecte : conversations spontanées dual‑canal, recrutement via la communauté Voice Arena, contrôle qualité automatisé (ID langue, détection playback, SNR, DNSMOS P.808) et protocole de transcription humain en cinq niveaux avec séparation des tâches.
- Intégration au leaderboard : Indian‑English visible dans la colonne par défaut (contribue à l’Average WER) ; Hindi disponible dans l’onglet Multilingual. Les splits publics permettent l’auto‑évaluation, les privés sont évalués par l’équipe Hugging Face.

## Points clés
- Le framework Sentence-Transformers (MultiVectorEncoder + MultiVectorEncoderTrainer) permet aujourd’hui d’entraîner et d’évaluer des modèles late-interaction sur des GPU consommateurs ; exemple reproductible : mLateOn-medical entraîné en 14,5 h sur une RTX 3090. (Disponible maintenant)
- Point d’optimisation décisif : partir d’un checkpoint "pre-supervised" ou d’un backbone + projection fraîche donne une meilleure adaptation de domaine qu’un checkpoint déjà supervisé. (Disponible maintenant)
- Gestion des documents longs : lever la coupure native des checkpoints (model_max_length) et configurer la longueur documentaire améliore fortement la qualité (+0.08 à +0.24 NDCG@10 selon tests). mLateOn supporte jusqu’à 8192 tokens. (Disponible maintenant)
- Pour l’entraînement avec paires question‑passage, la perte standard est MultiVectorMultipleNegativesRankingLoss ; sa variante Cached/GradCache permet de simuler gros batchs malgré mémoire GPU limitée (mini_batch_size vs effective batch). (Disponible maintenant)
- Coût d’indexation : index multi‑vecteur brut pour 200k passages ≈ 45 GB (fp16) ; combinaisons token‑pooling + quantization + pruning réduisent fortement la taille (ex. réduction ≈ 13× avec perte NDCG mineure). (Disponible maintenant / à tester selon méthode choisie)
- Données d’impact rapide : 100k paires (~75 minutes d’entraînement) approchent le résultat d’un million de paires (écart ≈ 0.012 NDCG@10). (Disponible maintenant)
